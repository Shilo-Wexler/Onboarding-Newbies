# Kerberos Core Concepts

# תשובה 1

Kerberos זה פרוטוקול של אימות 
הבעיה שהוא בא לפתור זה את היכולת לאמת זהות ברשת פנימית מבלי להצטרך לשוח סיסמאות ברשת 
הוא משתמש בחותמת זמן כדי למנוע התקפות של הקלטה ואז שימוש 
ומאפשר להזדהות פעם אחת ביום ואז לקבל גישה רציפה לכל השירותים והשרתים שיש במרשתת 
--
הרכיבים 
--
Principal שזה המזהה היחודי של כל משתמש שרת או שירות ברשת 
--
KDC שזה השרת המרכזי שאחראי לניהול של האימות וזה למעשה השרת היחיד שמחזיק את כל הנתונים והסודות (כמו ה ash של הסיסמאו)
ודרכו מוציאים את התגים של ההזדהות ומפתחות ההצפנה 
--
TGT הטיקט הראשוני לזיהוי של המשתמש שהוא בעצם תחליף לסיסמא ואיתו אפשר לגשת לשירותים במהלך היום 
--
Service Ticket טיקט חד פעמי שמיועד לאחסון או לשרת ספציפי הוא מוצפן עם המפתח של שרת היעד ואז רק שרת היעד יכול לפתוח את הטיקט הזה
--
Keytab קובץ שנמצא בכל אחד מהשרתים או קונטיינרים ומכיל את מפתח ההצפנה לפענח את Service Ticket 
--

# LDAP Core Concepts


# תשובה 1
אימות זה לוודא מי המשתמש 
הרשאה זה לבדוק האם למשתמש המאומת הזה יש אישור לגשת לקובץ מסויים או לתוכנה מסויימת 

LDAP  (Kerberos כשהו במבנה המשולב עם )  משמש כדי לבדוק לאחר שהמשתמש זוהה איזה הרשאות ותוכנות הוא יכול לגשת אליהם ואיז לא 
וזה קורה על ידי חלוקה לקבוצות וזיהוי כמבנה של עץ קבצים 

# תשובה 2

פעולת הזדהות. הלקוח שזה יכול להיות משתמש או מערכת מגיש שם וסיסמא כדי לפתוח ערוץ מול השרת ולקבל אישור לגשת לנתונים 
--
מאפשר לחפש (בנוי בצורה היררכית כמו עץ הקבצים בלינוקס ) וניתן לבקש ולקבל לפי קבוצות 
--
אפשר לעדכן למחוק או להוסיף משתמשים והרשאות 
--
Compare מאפשר לקבל true false על שאלה כמו האם המשתמש x שייך לקבוצה y 
--
פעולת Unbind לאחר ההזדהות וקבלת המידע התנתקות יזומה של החיבור עם מבקש הבקשה 

# תשובה 3

Schema ב LDAP
זה בעצם  אוסף של כללים וחוקים שמגדירים איזה סוג מותר לשמור ואיך הוא מאורגן 

Object Classes תבנית מרכזית של סוג הרשומה כמו משתמש שרת קבוצות הרשאות וכדו 
Attributes ממש שדות ספציפיים  כמו מייל אצל משתמש וכדו 

הסכמה חשובה כיוון שהיא מאפשרת אחידות שטובה עבור סקריפטים וגם של האפליקציות יוכלו לפנות לאותו שדה ולא יהיו שינוים 
וגם זה כופה על האמינות של הנתונים שלא יהיו שדות חשובים שהם יוותרו ריקים 

# תשובה 4

זה מסודר במנה דומה לעץ תקיות
והמבנה נקרא DIT (Directory Information Tree) 
השורש של העץ מייצג בדכ את הדומיין של הארגון  ואז כל תקייה יהא מחלקה מסויימת וגרופ של הרשאות מסויימות 
והעלה בסוף יהיה המשתמש או השרת וכל הנתיב אליו יהיה מש שיקבע את ההרשאות שלו

ולדוגמא עם עןבד עוזב את החברה יש רק מקום אחד להסיר והוא מוסר מכלל השירותים מיד
